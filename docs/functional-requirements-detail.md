# 기능 요구사항 상세 (확정 사항)

> 상위 문서: [functional-requirements.md](functional-requirements.md), [assignment.md](assignment.md)
> 이 문서는 협의를 거쳐 **확정된 내용**을 정리한다. 현재 미확정 항목은 없다.
>
> **변경 이력**
> 1. 입고/출고를 즉시 엑셀에 반영하는 방식에서 "수정을 마친 뒤 [저장]을 누르면 반영"하는 방식으로 변경했다.
> 2. 엑셀 파일 첨부 기능(FR-04)을 추가했다.
> 3. 서버의 엑셀 파일을 직접 수정하는 방식을 버리고, **첨부 → 메모리에서 편집 → 저장(메모리 확정) → 다운로드** 방식으로 변경했다. 서버는 파일을 쓰지 않는다.

## 0. 상태 모델

```
업로드 또는 시작 시 예시 데이터
        │
        ▼
   저장본(메모리) ◀──── [저장] ──── 작업본(메모리) ◀── 입고/출고
        │                              │
        │                         [되돌리기]로 저장본 상태 복원
        ▼
   [다운로드] → 수정된 .xlsx 파일
```

| 용어 | 설명 |
|------|------|
| 저장본 | [저장]으로 확정된 값. 다운로드할 때 파일에 기록되는 값 |
| 작업본 | 입고/출고가 반영된 편집 중인 값 |
| 변경된 품목 | 작업본 수량 ≠ 저장본 수량인 품목 |
| 내려받지 않은 저장 | 저장은 했지만 마지막 다운로드(또는 첨부/시작) 이후 다운로드하지 않은 상태 |

- 위 데이터는 모두 **사용자 세션 단위의 서버 메모리**에 있다.

## 1. 재고 조회 (FR-01)

| 항목 | 확정 내용 |
|------|-----------|
| 표시 항목 | 품목ID, 품목명, 현재 수량, 최종 수정일시 |
| 정렬 기준 | 등록순(파일의 행 순서) 고정 |
| 검색·필터 | 제외 |
| 재고 부족 표시 | 제외 |
| 화면 구성 | 조회, 변경, 저장, 첨부, 다운로드를 **한 화면**에서 처리 |
| 변경 표시 | 저장하지 않은 변경이 있는 품목은 행을 강조하고 저장된 수량 → 변경된 수량을 함께 보여준다 |
| 현재 파일 표시 | 지금 사용 중인 파일명을 화면에 보여준다 (예시 데이터는 `inventory.xlsx`) |

조회 화면의 "현재 수량"은 **작업본 기준**의 수량이다.

## 2. 재고 변경 (FR-02)

| 항목 | 확정 내용 |
|------|-----------|
| 입력 방식 | 품목별 수량 입력칸 + [입고]/[출고] 버튼 |
| 반영 시점 | 버튼을 누르면 **작업본에만** 반영한다 |
| 수량 검증 | 0 이상의 정수 |
| 수량 최소값 | 0 (입고/출고 수량 0 허용, 수량 0은 변경으로 보지 않는다) |
| 수량 상한 | 999,999,999,999,999 (15자리). 엑셀 숫자 정밀도(15자리)와 JS 안전 정수(2^53-1 = 9,007,199,254,740,991) 중 더 낮은 쪽 기준 |
| 상한 초과 | 입고 후 재고가 상한을 넘으면 거부하고 오류 메시지 표시 |
| 재고 초과 출고 | 작업본 수량보다 많이 출고하면 거부하고 오류 메시지 표시, 음수 재고 불가 |
| 입출고 이력 | 진행하지 않음 (저장·표시 안 함) |
| 결과 피드백 | 같은 화면에서 알림 메시지로 성공/실패 표시 |
| 동시 사용자 | 고려하지 않음. 데이터는 세션마다 독립이라 사용자끼리 서로 영향을 주지 않으며, 한 세션 안의 동시 요청 제어는 하지 않는다 |

## 3. 재고 저장 (FR-03)

| 항목 | 확정 내용 |
|------|-----------|
| 저장 시점 | 사용자가 **[저장]** 버튼을 눌렀을 때 |
| 저장 의미 | 작업본을 **서버 메모리의 저장본**으로 확정한다. 파일은 만들지 않는다 |
| 저장 대상 | 저장본과 작업본 수량이 다른 품목만 (입고 후 같은 수량을 출고해 원래대로 돌아온 품목은 제외) |
| 최종 수정일시 | 저장 시점의 시각으로 변경된 품목만 갱신 |
| 변경 없음 | 변경된 품목이 없으면 저장 버튼을 비활성화하고, 요청이 와도 아무것도 바꾸지 않는다 |
| 저장 성공 | "N건 저장 완료" 알림을 보이고, 화면에 "저장됨 · 아직 내려받지 않음"을 표시한다 |
| 되돌리기 | 저장하지 않은 변경을 모두 버리고 **마지막 저장 상태**로 복원한다 |

## 4. 엑셀 파일 첨부 (FR-04)

| 항목 | 확정 내용 |
|------|-----------|
| 첨부 방식 | 화면에서 `.xlsx` 파일을 선택해 업로드한다 (`.xls`, `.xlsm`, 그 밖의 형식은 거부) |
| 파일 크기 | 5MB 이하 |
| 첨부 후 동작 | 파일 내용을 **세션 메모리로 불러와** 현재 재고 데이터로 사용한다. 서버에는 파일을 저장하지 않는다 |
| 원본 보관 | 다운로드 시 서식을 유지하기 위해 업로드한 파일의 바이트를 세션 메모리에 보관한다 |
| 이전 데이터 | 첨부하면 이전 데이터(저장본, 작업본)가 대체된다. 저장하지 않은 변경이나 내려받지 않은 저장이 있으면 화면에서 확인을 받은 뒤 진행한다 |
| 검증 | 파일 전체를 먼저 검증하고, 하나라도 오류가 있으면 **아무것도 바꾸지 않는다** (기존 데이터 유지) |
| 오류 안내 | 오류가 난 행 번호와 이유를 알림에 보여준다 (최대 20건) |

### 4.1 첨부 파일 형식 규칙
- 시트: `재고` 시트를 사용한다. 없으면 첫 번째 시트를 사용한다.
- 1행은 헤더이며, A~D열이 아래 순서와 이름이어야 한다. D열은 생략할 수 있다.

| 열 | 헤더 | 필수 | 검증 |
|----|------|------|------|
| A | 품목ID | O | 1 이상의 정수, 중복 불가 |
| B | 품목명 | O | 공백만 있는 값 불가 |
| C | 현재 수량 | O | 0 ~ 999,999,999,999,999의 정수 (소수, 음수, 문자, 수식 불가) |
| D | 최종 수정일시 | 선택 | 비어 있거나 날짜/시간 값. 비어 있으면 화면에 `-`로 표시 |

- 데이터 행은 2행부터이고, 완전히 빈 행은 건너뛴다.
- 데이터 행이 1개 이상 있어야 하고, 최대 1,000행까지 허용한다.
- 품목 순서는 파일의 행 순서(등록순)를 따른다.

## 5. 엑셀 파일 다운로드 (FR-05)

| 항목 | 확정 내용 |
|------|-----------|
| 다운로드 기준 | **저장본** 기준. 저장하지 않은 변경은 포함되지 않는다 |
| 저장하지 않은 변경이 있을 때 | "저장하지 않은 변경 N건은 포함되지 않습니다. 계속하시겠습니까?"를 확인한 뒤 내려받는다 |
| 파일 내용 | 첨부한 원본 파일(또는 예시 데이터 파일)을 기반으로 각 품목의 `현재 수량`과 `최종 수정일시`만 갱신한다. 서식, 다른 열, 다른 시트는 유지된다 |
| 원본에 D열이 없을 때 | 헤더 `최종 수정일시`를 추가하고 값을 채운다 |
| 파일명 | `{원본 파일명}_수정_yyyyMMdd_HHmmss.xlsx` (예: `inventory_수정_20261111_152041.xlsx`) |
| 다운로드 후 | "내려받지 않은 저장" 표시를 해제한다. 저장본과 작업본은 그대로이다 |
| 데이터 변경 | 다운로드는 메모리의 데이터를 바꾸지 않는다 |
| 수식 재계산 | 원본의 다른 수식이 수량을 참조할 수 있으므로, 엑셀이 파일을 열 때 다시 계산하도록 표시한다 |

## 6. 데이터 및 아키텍처

### 6.1 초기 데이터
- 과제의 예시 데이터를 담은 엑셀 파일을 만들어 프로젝트에 포함한다 (`src/main/resources/sample/inventory.xlsx`).
- 새 세션이 시작되면 이 파일을 메모리에 불러와 초기 데이터로 쓴다. 사용자가 파일을 첨부하지 않아도 바로 사용할 수 있다.
- 사용자가 다른 엑셀 파일을 첨부하면 4장에 따라 그 파일로 대체된다.

| 품목ID | 품목명 | 현재 수량 | 최종 수정일시 |
|--------|--------|-----------|---------------|
| 1 | 무선마우스 | 30 | (생성 시각) |
| 2 | 키보드 | 20 | (생성 시각) |
| 3 | USB 메모리 | 50 | (생성 시각) |

### 6.2 엑셀 처리 방침
- **DB와 서버 파일 저장소를 쓰지 않는다.** 데이터는 사용자 세션의 메모리에만 있다.
- Apache POI로 첨부 파일을 읽고(검증 포함), 다운로드할 때 원본 파일을 열어 값을 갱신해 내려준다.
- 서버가 파일을 쓰지 않으므로 파일 경로 고정, 파일 잠금, 임시 파일 교체 문제가 없다.

### 6.3 데이터 보존 범위
- 세션 메모리의 데이터는 **브라우저를 새로고침해도 유지**된다.
- **서버를 재시작하거나 세션이 만료되면 사라진다.** 세션이 만료되면 예시 데이터로 다시 시작하며, 화면의 현재 파일명으로 이를 알 수 있다.
- 세션 만료 시간은 8시간으로 설정한다.
- 저장하지 않은 변경이나 내려받지 않은 저장이 있는 동안 화면에 항상 표시하고, 페이지를 떠날 때 경고한다.

### 6.4 화면·API 구조
- Thymeleaf는 **데이터가 없는 화면(껍데기)만 렌더링**한다.
- 데이터 조회와 변경은 **별도 API**로 제공하고, 화면은 **CSR(클라이언트 사이드 렌더링)** 로 API를 호출해 그린다.

### 6.5 제외 범위
- 품목 신규 등록·삭제
- 인증·권한
- 검색·필터, 재고 부족 표시, 입출고 이력
- 동시 사용자 요청 처리 (락, 충돌 감지, 최신값 동기화 등)
- 첨부 파일의 병합(기존 데이터와 합치기), `.xls`/`.xlsm` 지원
- 서버에 파일 저장, 데이터의 영구 보관 (서버 재시작 시 소실)
