# 테스트 전략

> 근거: [functional-requirements-detail.md](functional-requirements-detail.md), [design.md](design.md), [api-design.md](api-design.md)

## 1. 원칙

- 테스트는 **도메인 단위 테스트**와 **통합 테스트** 두 종류로 진행한다.
- 케이스는 최소화하고 **핵심 기능만** 검증한다. 모든 경계값을 나열하지 않는다.
- 엑셀 파일은 테스트 코드에서 Apache POI로 직접 만들어 쓴다. 별도의 테스트용 파일은 두지 않는다.
- 테스트는 서로 독립적이어야 하며 실행 순서에 의존하지 않는다.

## 2. 테스트 구성

| 구분 | 대상 | 방식 | 케이스 수 |
|------|------|------|-----------|
| 도메인 단위 테스트 | 도메인 객체(`Item`, `Quantity`), 수량 규칙, 저장/되돌리기, 엑셀 파싱/내보내기 | 스프링 없이 순수 JUnit 실행 | 12 (UT-07은 테스트 메서드 2개) |
| 통합 테스트 | API 전체 흐름 (요청 → 서비스 → 세션 메모리 → 엑셀 변환 → 응답) | `@SpringBootTest` + `MockMvc` | 5 |

### 2.1 도구
- JUnit 5, AssertJ
- 통합 테스트: `@SpringBootTest`, `@AutoConfigureMockMvc`, `MockHttpSession` (현재 `build.gradle`의 `webmvc-test`로 충분하다)
- 엑셀 생성/검증: Apache POI

### 2.2 위치와 실행
- 위치: `src/test/java/com/inventorysystem/`
  - 단위 테스트: `domain/`, `service/`, `excel/`
  - 통합 테스트: `integration/`
- 실행: `./gradlew test`
- 기존 `InventorySystemApplicationTests`(컨텍스트 로드)는 통합 테스트 안에서 대체되므로 필요하면 삭제한다.

## 3. 도메인 단위 테스트

대상 클래스는 `domain` 패키지의 `Item`, `Quantity`와 `InventorySession`(저장본/작업본 규칙), `ExcelItemParser`, `ExcelExporter`이다. `domain` 패키지의 클래스는 다른 클래스에 의존하지 않으므로 가장 먼저, 가장 단순하게 검증한다.

### 3.1 수량·저장 규칙 (`InventorySession`)

| ID | 시나리오 | 기대 결과 |
|----|----------|-----------|
| UT-01 | 입고/출고 후 작업본 수량 확인 (키보드 20에 입고 5, 출고 3) | 작업본 22, 저장본 20 그대로, `changed = true`, `dirty = true` |
| UT-02 | 작업본보다 많이 출고 / 입고 후 상한 초과 / 정수가 아니거나 범위 밖의 수량 | 각각 예외 발생, 수량은 변하지 않음 |
| UT-03 | 입고 후 같은 수량을 출고해 원래대로 돌아옴 | `changed = false`, `dirty = false` (저장 대상 아님) |
| UT-04 | 저장 | 변경된 품목만 저장본이 작업본 값으로 바뀌고 최종 수정일시 갱신, 변경 없는 품목은 그대로, `unexported = true`, `dirty = false` |
| UT-05 | 저장 후 다시 변경하고 되돌리기 | 작업본이 **마지막 저장 상태**로 복원됨, 저장본과 `unexported`는 그대로 |

### 3.2 엑셀 변환 (`ExcelItemParser`, `ExcelExporter`)

| ID | 시나리오 | 기대 결과 |
|----|----------|-----------|
| UT-06 | 정상 파일 파싱 (예시 데이터 3건, D열 없음 포함) | 행 순서대로 품목 3건, 수량/품목명 일치, 최종 수정일시 없음 |
| UT-07 | 잘못된 파일 파싱 (수량이 소수/음수/문자/수식, 품목ID 중복, 헤더 불일치 중 하나 이상) | 예외 발생, 메시지에 오류 행 번호와 이유가 들어 있음 |
| UT-08 | 내보내기 후 다시 읽기 | 저장본 수량과 최종 수정일시가 파일에 반영되고, 원본의 다른 열과 다른 시트는 유지됨 |
| UT-09 | 작업본에만 있는 변경이 있는 상태로 내보내기 | 파일에는 **저장본 수량**만 기록되고 작업본 수량은 포함되지 않음 |

### 3.3 도메인 객체 (`Item`, `Quantity`)

| ID | 시나리오 | 기대 결과 |
|----|----------|-----------|
| UT-10 | `Item`을 만든 직후 | 저장본 수량 = 작업본 수량, `changed = false`, 최종 수정일시와 원본 행 위치가 입력한 값 그대로 |
| UT-11 | `Item`의 수량을 바꾸고 확정/복원 | 수량을 바꾸면 `changed = true`이고 저장본은 그대로, 저장된 값으로 되돌리면 `changed = false`, `commit`하면 저장본 = 작업본이 되고 최종 수정일시가 갱신됨, `revert`하면 작업본이 저장본으로 복원됨 |
| UT-12 | `Quantity` 상수 | `MIN = 0`, `MAX = 999,999,999,999,999`이고 `MAX`는 15자리이며 JS 안전 정수(2^53-1) 이하 |

## 4. 통합 테스트

`@SpringBootTest`로 전체 애플리케이션 컨텍스트를 띄우고 `MockMvc`로 API를 호출한다. 세션 메모리를 확인해야 하므로 한 시나리오 안에서는 **같은 `MockHttpSession`을 재사용**한다. 테스트마다 새 세션을 만들어 서로 영향을 주지 않게 한다.

| ID | 시나리오 | 호출 흐름 | 기대 결과 |
|----|----------|-----------|-----------|
| IT-01 | 초기 조회 (FR-01) | `GET /api/items` | 200, 무선마우스 30 / 키보드 20 / USB 메모리 50이 등록순으로 나오고 `fileName = inventory.xlsx`, `dirty = false`, `unexported = false` |
| IT-02 | 입고·출고·저장·되돌리기 흐름 (FR-02, FR-03) | 키보드 입고 → USB 출고 → `GET` → 저장 → 다시 입고 → 되돌리기 | 입고/출고 후 `changed`·`dirty` 반영, 저장 후 `savedQuantity`가 바뀌고 `unexported = true`, 되돌리기 후 마지막 저장 상태로 복원 |
| IT-03 | 오류 응답 형식 | 재고보다 많은 출고, 존재하지 않는 품목ID로 입고 | 둘 다 400, 본문은 `message`만 있고 코드/상세 필드는 없음, 이후 조회 시 데이터 변화 없음 |
| IT-04 | 첨부 → 수정 → 저장 → 다운로드 (FR-04, FR-05) | 엑셀 업로드 → 입고 → 저장 → 출고(저장 안 함) → 다운로드 | 업로드 후 파일 내용으로 조회, 다운로드 응답이 `.xlsx`이고 파일명이 `{원본명}_수정_…xlsx`, 내려받은 파일에는 **저장한 변경만** 반영되고 저장하지 않은 출고는 빠져 있음, 다운로드 후 `unexported = false` |
| IT-05 | 잘못된 엑셀 첨부 | 오류가 있는 엑셀 업로드 (행 오류 포함) | 400, `message`에 행별 이유가 있고, 이후 조회 시 **기존 데이터가 그대로** 유지됨 |

## 6. 범위에서 제외

- 화면(JavaScript, HTML) 테스트 — 화면 동작은 수동으로 확인한다.
- 동시 요청, 세션 만료, 서버 재시작 후 소실
- 성능, 대용량 파일, 보안 테스트
- 500 오류 경로 (예기치 못한 오류는 자동화하지 않는다)
- 모든 경계값 조합 (대표 케이스만 검증한다)

## 7. 수동 확인 항목

자동화하지 않는 화면 동작은 구현 후 아래만 직접 확인한다.

1. 최초 접속 시 예시 데이터 3건이 표시된다.
2. 입고/출고 시 행이 강조되고 `20 → 25` 형식으로 보인다.
3. [저장] 후 "아직 내려받지 않았습니다"가 보이고 [다운로드]가 강조된다.
4. 저장하지 않은 변경이 있을 때 다운로드/업로드/페이지 이탈 경고가 나타난다.
5. 오류가 있는 엑셀을 올리면 행별 오류가 알림에 보인다.
