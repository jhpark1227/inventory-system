# 화면 설계 문서

> 상위 문서: [design.md](design.md) · API 설계: [api-design.md](api-design.md)
> 근거: [functional-requirements-detail.md](functional-requirements-detail.md)

## 1. 개요

- 화면은 `/` 한 페이지이며, 조회, 변경, 저장, 엑셀 첨부, 엑셀 다운로드를 모두 이 화면에서 처리한다.
- Thymeleaf는 데이터 없는 골격만 렌더링하고, 표의 내용은 브라우저에서 API를 호출해 그린다 (CSR).
- 입고/출고는 작업본에만 반영되고, **[저장]** 으로 서버 메모리의 저장본에 확정된다.
- 수정된 엑셀 파일은 **[다운로드]** 로 내려받는다. 서버에는 파일이 남지 않는다.

## 2. 화면 구성

```
┌────────────────────────────────────────────────────────────────────────┐
│ 소모품 재고 관리                                                         │
│ 현재 파일: inventory.xlsx                                                │
│ 엑셀 파일 가져오기: [파일 선택] 재고현황.xlsx   [업로드]                   │
│                                                                         │
│ [되돌리기]  [저장 (1)]  [다운로드]                                        │
│ ● 저장하지 않은 변경이 1건 있습니다.                                      │
│ ● 저장됨 · 아직 내려받지 않았습니다.                                      │
│ [알림 영역: 성공/실패 메시지]                                             │
├──────┬────────────┬─────────────┬───────────────────┬──────────────────┤
│ 품목ID │ 품목명     │ 현재 수량    │ 최종 수정일시       │ 재고 변경         │
├──────┼────────────┼─────────────┼───────────────────┼──────────────────┤
│ 1    │ 무선마우스  │ 30          │ 2026-11-11 11:30  │ [수량] [입고] [출고] │
│ 2    │ 키보드      │ 20 → 25     │ 2026-11-11 11:30  │ [수량] [입고] [출고] │  ← 강조
│ 3    │ USB 메모리  │ 50          │ 2026-11-11 11:30  │ [수량] [입고] [출고] │
└──────┴────────────┴─────────────┴───────────────────┴──────────────────┘
```

| 영역 | 내용 |
|------|------|
| 제목 | 소모품 재고 관리 |
| 현재 파일 | 지금 사용 중인 파일명. 세션이 만료되어 예시 데이터로 돌아간 경우도 이것으로 알 수 있다. |
| 엑셀 첨부 | `.xlsx` 파일 선택 버튼, 선택한 파일명, [업로드] 버튼. 파일을 고르기 전에는 [업로드]가 비활성화된다. |
| 작업 버튼 | [되돌리기], [저장 (N)], [다운로드]. 저장 버튼에는 변경된 품목 수를 함께 표시한다. |
| 상태 줄 | 해당 상태일 때만 보인다. ① `dirty`: "저장하지 않은 변경이 N건 있습니다." ② `unexported`: "저장됨 · 아직 내려받지 않았습니다." |
| 알림 영역 | 처리 결과 메시지 (성공/실패) |
| 재고 표 | 품목ID, 품목명, 현재 수량, 최종 수정일시, 재고 변경 입력 |
| 재고 변경 | 수량 입력칸 + [입고] + [출고] 버튼 (행마다) |

### 2.1 현재 수량 열 표시
- 변경이 없는 품목: 수량만 표시한다 (`30`).
- 변경된 품목: `저장된 수량 → 작업본 수량` 형식으로 표시하고 행 배경을 강조한다 (`20 → 25`).
- 최종 수정일시는 마지막으로 저장된 시각이며, 저장 전에는 바뀌지 않는다. 값이 없으면 `-`로 표시한다.

### 2.2 [다운로드] 버튼 강조
- `unexported`가 `true`이면 [다운로드]를 주요 버튼 스타일로 강조해, 저장 후 파일 받기를 잊지 않도록 한다.

## 3. 동작

| 동작 | 설명 |
|------|------|
| 최초 로드 / 새로고침 | `GET /api/items`로 데이터를 받아 표를 그린다. 세션에 남아 있는 저장본, 작업본, 상태 줄을 그대로 표시한다. |
| 입고/출고 클릭 | 해당 행의 수량으로 API를 호출한다. 처리 중에는 그 행의 버튼을 비활성화한다. |
| 입고/출고 성공 | 해당 행을 응답 값으로 갱신하고 상태 줄과 저장 버튼의 건수를 갱신한다. "키보드 5개 입고 반영 (저장 전)" 알림을 보이고 수량 입력칸을 비운다. |
| 입고/출고 실패 | 서버가 준 `message`를 알림에 보이며 표는 바꾸지 않는다. |
| 저장 클릭 | 확인 없이 `POST /api/items/save`를 호출한다. |
| 저장 성공 | 응답의 목록으로 표를 다시 그리고 "N건 저장 완료. 파일로 받으려면 [다운로드]를 누르세요." 알림을 보인다. 강조가 사라지고 `unexported` 상태 줄이 나타난다. |
| 되돌리기 클릭 | "저장하지 않은 변경 N건을 모두 버립니다. 계속하시겠습니까?" 확인 후 `POST /api/items/discard`를 호출하고 응답으로 표를 다시 그린다. |
| 파일 선택 | 선택 즉시 브라우저에서 1차 검사한다: 확장자가 `.xlsx`인지, 5MB 이하인지. 맞지 않으면 알림으로 안내하고 선택을 취소한다. |
| 업로드 클릭 | 확인창을 띄운다. 기본 문구는 "현재 재고 데이터가 선택한 파일의 내용으로 바뀝니다. 계속하시겠습니까?"이다. `dirty`이면 "저장하지 않은 변경 N건도 사라집니다.", `unexported`이면 "내려받지 않은 저장 내용도 사라집니다."를 덧붙인다. 확인하면 `POST /api/items/upload`(`multipart/form-data`)를 호출한다. |
| 업로드 성공 | 응답의 목록으로 표를 다시 그리고 "N개 품목을 불러왔습니다." 알림을 보인다. 현재 파일명을 갱신하고 파일 선택 상태를 초기화한다. |
| 업로드 실패 | 알림에 서버 `message`를 줄바꿈을 유지해 보인다 (행별 오류가 최대 20건 들어 있다). 표와 데이터는 그대로 둔다. |
| 다운로드 클릭 | `dirty`이면 "저장하지 않은 변경 N건은 파일에 포함되지 않습니다. 계속하시겠습니까?"를 확인한다. 확인하면 `GET /api/items/download`를 `fetch`로 받아 브라우저 다운로드를 실행한다. |
| 다운로드 성공 | "파일을 내려받았습니다." 알림을 보이고 `GET /api/items`로 상태를 갱신해 `unexported` 상태 줄을 없앤다. |
| 다운로드 실패 | 서버 `message`를 알림에 보인다. 상태는 그대로 둔다. |
| 통신 실패 | "서버와 통신할 수 없습니다." 알림을 보인다. |

처리 중(요청이 진행되는 동안)에는 모든 버튼을 비활성화해 중복 요청을 막는다.

### 3.1 버튼 활성 조건

| 버튼 | 활성 조건 |
|------|-----------|
| 저장 | `dirty`가 `true`이고 요청 처리 중이 아닐 때 |
| 되돌리기 | `dirty`가 `true`이고 요청 처리 중이 아닐 때 |
| 다운로드 | 요청 처리 중이 아닐 때 (저장 내용이 없어도 내려받을 수 있다) |
| 입고 / 출고 | 요청 처리 중이 아닐 때 |
| 업로드 | 파일을 선택했고 요청 처리 중이 아닐 때 |
| 파일 선택 | 요청 처리 중이 아닐 때 |

### 3.2 페이지를 떠날 때
- `dirty`이거나 `unexported`이면 탭을 닫거나 이동할 때 브라우저 기본 확인창(`beforeunload`)으로 경고한다.
- 데이터는 서버 세션 메모리에 남아 새로고침해도 유지되지만, 서버를 재시작하거나 세션이 만료되면 사라진다. 상태 줄이 이를 알려준다.

## 4. 입력 처리

- 수량 입력칸은 `type="text"` + `inputmode="numeric"`로 두고 숫자만 허용한다. `type="number"`는 큰 수에서 소수 처리와 표시 문제가 생길 수 있어 쓰지 않는다.
- 브라우저에서 1차 검증(빈 값, 숫자 여부, 0 이상, 상한)을 하되, 최종 검증은 서버가 한다.
- 수량 표시는 천 단위 구분 쉼표를 사용한다.
- 최종 수정일시는 `yyyy-MM-dd HH:mm`으로 표시한다.

## 5. 알림 규칙

| 구분 | 표시 |
|------|------|
| 성공 | 성공 색상(예: 녹색)으로 결과 요약 |
| 실패 | 오류 색상(예: 적색)으로 서버 메시지 |
| 교체 | 새 알림이 오면 이전 알림을 교체한다. |
| 상태 줄 | 알림과 별개로 해당 상태인 동안 계속 보인다. 저장하지 않은 변경은 주의 색상(예: 주황), 내려받지 않은 저장은 안내 색상(예: 파랑)을 쓴다. |

## 6. 파일 구성

| 파일 | 역할 |
|------|------|
| `src/main/resources/templates/index.html` | 데이터 없는 골격 (제목, 현재 파일, 엑셀 첨부 영역, 작업 버튼, 상태 줄, 알림 영역, 표 머리) |
| `src/main/resources/static/js/app.js` | 조회, 표 렌더링, 입출고·저장·되돌리기·업로드·다운로드 호출, 입력 검증 |
| `src/main/resources/static/css/style.css` | 스타일 (변경 행 강조, 다운로드 버튼 강조 포함) |
